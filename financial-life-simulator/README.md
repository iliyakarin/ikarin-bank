# Financial Life Simulator

Autonomous background service running alongside KarinBank that simulates a realistic, ongoing "financial life" for two demo personas.

The simulator interacts purely via the real backend REST API (no direct DB manipulation). Every simulated event executes through standard authentication, ownership verification, business logic, outbox event generation, and Kafka streaming.

---

## Simulated Financial Events

| Event | Default Cadence | Primary Persona | Counterparty / Target | Amount |
|---|---|---|---|---|
| **Salary Deposit** | 1st & 15th of each month | `ikarin@admin.com` | Employer Payroll | $2,500.00 (`SALARY_AMOUNT_CENTS`) |
| **Rent Payment** | 1st of each month | `ikarin@admin.com` (debit) | Landlord / Property | $1,800.00 (`RENT_AMOUNT_CENTS`) |
| **Car Insurance** | 5th of each month | `ikarin@admin.com` (debit) | Geico Insurance | $120.00 (`CAR_INSURANCE_AMOUNT_CENTS`) |
| **Merchant Purchases** | Dynamic stochastic (~35%–50% per tick) | `ikarin@admin.com` | Austin Energy, T-Mobile, Groceries | Varies by category |
| **P2P Transfers** | Dynamic stochastic (~20%–25% per tick) | `ikarin@admin.com` ⇄ `ikarin6@example.com` | Reciprocal friend transfer | Random $10.00 – $150.00 |

### Dynamic Day/Night Activity Multiplier
- **Daytime Ticks (08:00–22:00 local):** Activity multiplier of `1.5x`.
- **Nighttime Ticks (22:00–08:00 local):** Scaled down to `0.4x` for realistic diurnal transaction patterns.

## Cadence & Configuration

The simulation cadence was tuned to ensure continuous, fresh activity for testing and live demonstrations:
- **Default Tick Interval:** **300 seconds (5 minutes)** (reduced from 3600s).
- **Auto-Settlement Integration:** Transactions generated by the simulator are automatically transitioned from `processing` to `cleared` within 45 seconds by the `backend/sync_checker.py` auto-settlement worker.

### Environment Variables

```bash
API_BASE_URL=http://api:8000                  # Internal Docker network API address
ADMIN_EMAIL=ikarin@admin.com                  # Admin persona email
ADMIN_PASSWORD=...                            # Admin persona password
SIM_USER2_EMAIL=ikarin6@example.com           # Counterparty persona email
SIM_USER2_PASSWORD=...                        # Counterparty password (auto-registered if absent)
SIMULATOR_SERVICE_KEY=...                     # Trusted service key matching backend configuration

# Simulation Cadence Tuning (optional overrides)
SIM_TICK_INTERVAL_SECONDS=300                 # Seconds between simulation ticks (default: 300)
SIM_PURCHASE_CHANCE=0.5                       # Probability of merchant purchase per tick
SIM_P2P_CHANCE=0.25                           # Probability of P2P transfer per tick
STATE_DB_PATH=/tmp/simulator_state.db         # Path to SQLite state file tracking execution history
```

## Control & Health API (Port 8004)

- `GET /health` — Simple liveness check.
- `GET /status` — Returns last tick timestamp, configured cadence, and recently fired events.
- `POST /trigger/{event_type}` — Forces immediate execution of an event, bypassing calendar gating:
  - Supported `event_type`: `salary`, `rent`, `insurance`, `purchase`, `p2p`.
  - Useful for live product demos and automated test fixtures.

### Production Healthcheck

Configured in `docker-compose.prod.yml`:
```yaml
healthcheck:

  interval: 30s
  timeout: 5s
  retries: 3
```

## Backend Integration Details

1. **Cloudflare Turnstile Bypass:** The simulator transmits the `X-Service-Key` header validated via `backend/routers/auth.py`'s `_is_trusted_service()`, allowing automated session creation without human CAPTCHA interaction.
2. **Salary Inflow via Admin Credit:** Uses `POST /admin/credit` to simulate external salary deposits into the primary account ledger.
3. **Resilient Token Management:** Re-authenticates personas dynamically at the start of each simulation tick.
